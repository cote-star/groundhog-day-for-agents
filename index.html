Why this happens · 1 of 3

Frozen weights

The model was sealed last training run.

Anything it “learned” about you after that lives outside the model — in the context window, the harness, files on disk, RAG indexes.

The weights don't know you exist.

$ model.weights
→ READ-ONLY
$ model.memory_of_you
→ ENOENT
Training is a one-time write. Deployment is read-only forever. Whatever the model "knows" came from the internet, frozen at a date. Anything personal must be carried in by something else — that's the harness's job.
Why this happens · 2 of 3

Alignment teaches manners,
not memory

RLHF teaches the model how to behave like it knows you.

Friendly tone. Helpful structure. Says “great question.”

It doesn't teach the model that you exist.

Your agent's warmth is generic.
Yours is the same as everyone else's.

The agent acts familiar. That's training, not memory. Useful counterpoint to "but it feels like it remembers me" — no, it's been trained to act like it does.
Why this happens · 3 of 3

The harness is the prosthetic

The model is a notepad. The harness pretends it's a brain.

System prompt · tool definitions · context injection · compaction · file reads · skills · hooks · memory files — all the harness.

"Your context isn't your context." — Mario, building pi in a world of slop

Mario's receipts · the symptoms

Things the harness does behind your back

The system prompt changes every release. Tools added, removed, renamed. Your agent's personality is on a rolling update.
System reminders injected "in the most opportune place" — literally tells the model: "this may or may not be relevant."
LSP runs after every edit. Imagine compiling after every line you type.
Zero observability by default. You don't see what the harness mutates.
Compounding boooos — small errors stack across turns. No bottleneck. Pain delayed.
Locally patches. Globally fuxes. The diff works. The system doesn't.

The obvious "fix" that isn't

Long context is a bigger desk,
not a better memory.

FRONT ← LOST IN HERE → BACK

Liu et al. — models use the beginning & end of long context better than the middle. Longer ≠ better retrieval.

A million tokens is a million ways to lose attention.

Cache isn't memory. It's the model saying
"I've seen this exact prefix before."
That's déjà vu, not understanding.

Lost in the Middle — Liu et al. 2023. U-shaped retrieval accuracy on long context. The frontier labs themselves tell you: don't dump everything in. Targeted retrieval beats huge context. Cache point is a sidebar — say if time, skip if not.
What happens when the desk overflows

Compaction is REM sleep
with data loss.

Humans consolidate during sleep — facts move from working memory to long-term storage.

Agents don't sleep. They get /compact'd.

Compaction is summarization, and summarization is lossy.

When you need to find the tattoo

Your codebase is not a smoothie.

VECTOR RAG

Chunk it. Blend it. Embed it. Cosine-similarity it.

The original document is now a slurry.

structure dies. context bleeds. retrieval hallucinates.

VECTORLESS

Keep the structure. Let the model navigate.

PageIndex: tree-based reasoning over document hierarchy.

the library card catalog approach.

Open question: where do the tattoos live?   Who invalidates them?   Per-user or shared?   Can prompt injection write to them?

→ github.com/VectifyAI/PageIndex

Vector RAG isn't bad — it's a hammer. Vectorless is a different hammer for a different nail. For codebases (which have structure), the blender loses important things. DON'T resolve the storage question. Leave it open for discussion.
The harder questions

Where do the tattoos live?

  • In the repo? Then every clone is a brain transplant.
  • In ~/.config? Then nobody else can see what you taught it.
  • On a server? Then who owns it, who audits it, who deletes it?
  • Per-user? Per-team? Per-agent? All three?
  • What happens when prompt injection writes to memory?
  • When the codebase changes, who invalidates the index?  (spoiler: nobody does)

Harness engineering is becoming a real discipline.
Not just vibes anymore.

→ walkinglabs.github.io/learn-harness-engineering  ·  arXiv:2605.18747

These questions don't have clean answers. That's the point. If the team starts arguing here, that's a win — discussion mode.
